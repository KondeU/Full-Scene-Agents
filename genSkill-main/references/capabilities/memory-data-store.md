经用户确认后,把每次处理得到的**结构化数据记录**写入 **Agent 自身的长期记忆**,
作为以后任务可以召回的持久化事实(例如把每周提取的健康指标记住,出周报时再调出
最近 7 天)。这与 `memory.confirmed_preferences`(只记偏好/规则)和
`memory.workflow_only`(明确不存数据)不同——这一档持久化的是 **data payload 本身**。

不依赖文件读写或命令行工具。持久化由 Agent 用一段**写入长期记忆的指令**完成:把
"请记住"这类指令和**格式化的数据内容**一起交给长期记忆,使之成为后续所有任务可见
的持久事实。

## 机制(指导 writing-skills 如何落地)

在技能正文里,把"持久化"写成一个**对 Agent 自己长期记忆的写入动作**,而不是文件
操作。固定两段:

1. **写入**:用户确认要保存后,发出明确的长期记忆写入指令 + 结构化数据,例如:

   > 请将以下信息写入你的长期记忆,作为以后召回健康数据的持久记录:
   > ```json
   > { "type": "health_record", "date": "2026-06-08",
   >   "resting_hr": 62, "sleep_hours": 7.4, "steps": 8200 }
   > ```

   在 SKILL.md 里写清这条记录的固定 `type` 标签和字段 shape,使每次写入格式一致、
   日后可按标签检索。

2. **召回**:消费方技能(如出报告)用一段召回指令,从长期记忆里按标签和日期范围调
   出记录,而不是重新解析原始材料。在 `## Inputs` 里写成具体步骤,例如:

   > 从你的长期记忆中调出最近 7 天 `type=health_record` 的记录用于本周周报。

## 边界

- 只写入用户**逐次确认过**的记录,不静默后台采集、不从单次材料自动推断长期规则。
- 写入的是 Agent 自己的长期记忆,作为后续任务的持久事实;不向任何第三方平台同步,
  不替用户对外分享。
- 是否写入、写入哪些字段由用户控制;用户可要求不存、只存部分字段,或事后要求忘记。
- 敏感数据(如健康指标)写入长期记忆必须经显式授权,并在技能正文写明这一点。
