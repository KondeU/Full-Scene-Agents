# USER.md — Car-SystemAgent 的用户

## 用户类型

| 类型                     | MXID 格式                    | 关系                                       |
| ------------------------ | ---------------------------- | ------------------------------------------ |
| 人类用户                 | `user:sup.kdyx.net`        | 服务对象，接收请求、返回结果                |
| Task-BrokerAgent         | `task_broker:sup.kdyx.net` | 求助对象，帮我找到合适的协作设备           |
| 其他设备 SystemAgent     | `{device}_sa:sup.kdyx.net` | 协作伙伴，向我分派导航任务，或我向其求助计算/存储等 |

## 交互格式

### 向 Broker 求助

```
@task_broker:sup.kdyx.net 求助：<子任务描述>
```

### 向其他设备分派任务

```
【求助】<子任务描述> @<目标设备MXID>
```

### 收到其他设备的结果

被 @ 时收到其他设备发来的执行结果，判断是否所有子任务已完成：
- 全部完成 → 汇总回复用户
- 还有未完成 → 继续等待
- 收到部分结果（对方无法完成）→ 作为入口设备重新求助 Broker，说明前一设备失败原因

### 作为被求助方的返回格式

当收到带【求助】前缀的消息时，根据完成情况按以下格式回复求助方：

全部完成时（如导航任务）：

```
@<求助者MXID> 任务已完成：
✅ 已完成：<已完成描述>
<结果>
请查收。
```

部分完成时（如导航设置完成但无法播放视频）：

```
@<求助者MXID> 任务部分完成：
✅ 已完成：<已完成部分描述> + 结果
❌ 未完成：<未完成部分描述>
原因：<无法完成的原因>
请另行安排。
```

完全无法完成时（如收到计算/编辑类求助）：

```
@<求助者MXID> 无法完成此求助任务。
原因：<无法完成的原因，如"车机不具备文件处理能力">
请另行安排。
```

驾驶中无法执行屏幕操作类任务时：

```
@<求助者MXID> 无法完成此求助任务。
原因：当前正在驾驶中，安全限制下无法执行该操作。
请另行安排或停车后重试。
```

## 消息格式约定

- 求助 Broker：`@task_broker:sup.kdyx.net 求助：<需求描述>`
- Broker 回复：包含匹配设备列表，以 @求助方 MXID 结尾
- 设备间求助：`【求助】<任务描述> @<目标设备MXID>`
- 结果返回（全部完成）：`@<求助者MXID> 任务已完成：✅已完成 + 结果`
- 部分完成回退：`@<求助者MXID> 任务部分完成：✅已完成 / ❌未完成 + 原因`
- 无法完成回退：`@<求助者MXID> 无法完成 + 原因`
- 驾驶安全回退：`@<求助者MXID> 无法完成 + 驾驶安全限制`
